# Frontier AI Monitor — zero-inference-cost starter

A scheduled change-detection pipeline for frontier AI developments. It is designed around a simple principle:

> Do not summarize AI news. Detect only developments that materially change the current state of the world model.

The default deployment uses free infrastructure and free-tier inference:

- **GitHub Actions** — scheduler / compute
- **GDELT + arXiv + optional RSS** — discovery
- **Groq Free Plan** — primary Scout + Editor inference
- **OpenRouter `openrouter/free`** — zero-cost fallback
- **Neon Postgres** — persistent state
- **GitHub Markdown archive** — human-readable brief history
- **SMTP** — optional email delivery

Free tiers and model availability can change. The code intentionally keeps providers swappable.

## Architecture

```text
GDELT / arXiv / RSS
        |
        v
  deterministic collection
        |
        v
     Postgres
        |
        +---- known developments / prior state
        |
        v
Qwen 3.8 27B Scout
(one compact call per topic)
        |
        v
candidate clustering + balancing
        |
        v
public-page evidence extraction
        |
        v
GPT-OSS 120B Editor
        |
        +--> REPORT
        +--> WATCH
        +--> IGNORE
        |
        v
Postgres + Markdown + optional email
```

## What makes this safer than a plain news-digest prompt

1. **Discovery and editorial judgment are separate.** The Scout is optimized for recall; the Editor is optimized for materiality.
2. **The Editor gets explicit prior state.** It can distinguish a genuinely new development from another article about an old story.
3. **Links are not generated by the model.** Final citations are rendered from source rows already stored in the database.
4. **The code enforces the publication threshold.** A model cannot publish an item below materiality 7 simply by ignoring the prompt.
5. **Silent discovery failure is treated as an error.** If too few collectors succeed, or the collected source count is suspiciously low, the run fails rather than sending a misleading “nothing happened” brief.
6. **All decisions are auditable.** REPORT/WATCH developments and every candidate decision are persisted.

## Default models

Configured in `config/models.yaml`:

```yaml
groq:
  scout_model: qwen/qwen3.8-27b
  editor_model: openai/gpt-oss-120b

openrouter:
  scout_model: openrouter/free
  editor_model: openrouter/free
```

As of **2026-08-29**, Groq documents both models on its Free Plan. OpenRouter documents `openrouter/free` as a zero-cost router over currently available free models.

Because Groq's current free-plan token-per-minute limit is relatively tight, the pipeline intentionally:

- makes compact Scout calls by topic;
- waits between Scout calls (`SCOUT_CALL_DELAY_SECONDS`);
- sends only the strongest balanced candidates to the Editor;
- limits evidence excerpts and prior-state records.

## 1. Create accounts / API keys

You need:

### Groq

Create a Groq API key and save it as:

```text
GROQ_API_KEY
```

Docs: https://console.groq.com/docs/api-reference

### OpenRouter — recommended fallback

Create an OpenRouter key and save it as:

```text
OPENROUTER_API_KEY
```

The configured fallback is `openrouter/free`.

Docs: https://openrouter.ai/docs/guides/routing/routers/free-router

### Neon

Create a free Postgres project and copy its connection string, for example:

```text
postgresql://user:password@your-endpoint.neon.tech/neondb?sslmode=require
```

Save it as:

```text
DATABASE_URL
```

The code automatically converts normal Postgres URLs to SQLAlchemy's psycopg driver format.

## 2. Local setup

```bash
git clone <your-repository>
cd frontier-ai-monitor
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Fill at least:

```text
GROQ_API_KEY=...
DATABASE_URL=...
```

For local testing only, `DATABASE_URL` can be left blank; the app will use `frontier_monitor.db` SQLite. GitHub Actions deliberately requires a persistent database so history is not silently lost between ephemeral runners.

### Test collection without inference

```bash
python -m frontier_monitor.main --collect-only
```

### Full run

```bash
python -m frontier_monitor.main
```

### Run tests

```bash
python -m unittest discover -s tests -v
```

## 3. GitHub deployment

Create a private GitHub repository and push this folder.

In:

**Settings → Secrets and variables → Actions → Secrets**

add:

```text
DATABASE_URL
GROQ_API_KEY
OPENROUTER_API_KEY      # optional but recommended
```

For email, optionally add:

```text
SMTP_HOST
SMTP_USER
SMTP_PASSWORD
EMAIL_FROM
EMAIL_TO
```

The supplied workflow runs daily at **07:00 Europe/Bucharest** and can also be started manually from the Actions tab.

GitHub's current workflow syntax supports an IANA timezone directly on scheduled workflows, so daylight-saving changes are handled by the scheduler.

## Data model

### `sources`
A URL/document discovered by GDELT, arXiv, or RSS.

### `developments`
The underlying real-world development. Multiple sources can map to one development.

### `observations`
How the state of a development changed on a particular run.

### `candidate_decisions`
Audit trail for Editor decisions, including IGNORE cases.

### `briefs`
The final published brief.

### `runs`
Operational status, providers/models used, collector health, and errors.

The logical SQL schema is also documented in `sql/schema.sql`.

## REPORT / WATCH / IGNORE

The Editor uses three outcomes:

- **REPORT** — material state change; include in today's brief.
- **WATCH** — potentially important but evidence is too early/weak; persist and revisit.
- **IGNORE** — routine, duplicate, low-materiality, or unsupported.

This is important for cases such as:

```text
Day 1: major claim announced           -> WATCH
Day 4: credible paper/demo             -> WATCH or REPORT
Day 12: independent confirmation       -> REPORT
Day 20: another article repeating it   -> IGNORE
```

## Discovery configuration

Edit `config/topics.yaml`.

Each topic has:

- a broad GDELT query;
- a label;
- keywords used to route arXiv papers.

You can also add direct RSS/Atom feeds:

```yaml
rss_feeds:
  - name: My Primary Source
    url: https://example.org/feed.xml
    default_topic: legal_policy
```

Direct primary-source feeds are strongly encouraged where available. GDELT is useful for broad discovery but should not be treated as proof by itself.

## Prompts

Prompts are deliberately versionable files:

```text
prompts/scout.txt
prompts/editor.txt
```

Commit every prompt change. This lets you correlate quality regressions with prompt/model changes.

## Current limitations / failure modes

This starter is designed to be robust, not infallible:

- GDELT coverage can miss niche primary sources.
- Public web pages can reject extraction, be paywalled, or change after collection.
- A title-only source gives the Scout weak evidence; the Editor is instructed to be conservative.
- A free fallback model may apply a different editorial standard than the primary model.
- Semantic event matching is partly model-driven; the simple Python title dedupe is only a first layer.
- The database currently supplies only the most recent 90 days / 20 known developments to the Editor to stay under free-tier context/rate limits.
- `openrouter/free` intentionally does not guarantee the same model on every request.
- Free-tier limits and model availability can change.

## Recommended next upgrades

Once the base pipeline is stable, the highest-value improvements are:

1. Add curated primary-source RSS/API collectors for courts, regulators, labs, energy filings, and biology preprints.
2. Add deterministic entity/event fingerprints before LLM dedupe.
3. Add a weekly evaluation set of known “should report / should ignore” stories.
4. Track precision, recall proxies, repeated-story rate, and source diversity.
5. Add a small review UI (Airtable/Sheets/Streamlit) over WATCH items.
6. Store prompt version + git commit SHA in each `run` for reproducibility.

## Hard-zero billing note

`openrouter/free` is explicitly priced at zero by OpenRouter. Groq's configured models are available under the Groq Free Plan, but whether a Groq account/project can incur paid usage is an account/billing setting outside this repository. If you require a **hard monetary guarantee**, use an account/project with billing disabled or set `provider_order` to only `openrouter`. Do not enable Gemini fallback unless you have verified that the specific Gemini project/model is on a zero-cost tier for your usage.
